## Flagged Assumptions

- **FA-02-1.** Whether the email is changing is decided by exact string comparison with no lower-casing, mirroring `UpdateStaffRequest`. A case-only change therefore demands `current_password`, which is the stricter reading of D-02.
- **FA-02-2 (backstop edge).** In a true race, both requests pass validation and the `users.email` unique index makes the loser's write fail. That surfaces as a 500 (QueryException) rather than a 422. This is accepted as T-01-09 (low); converting it would add an exception-mapping path no decision asked for.
- **FA-02-3.** If a client sends `current_password` while not changing the email, it is still verified (`sometimes`), so a wrong value gives 422. The dashboard sends it only with an email change, so this is harmless and it will be documented in 01-04.

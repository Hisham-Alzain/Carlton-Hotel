<objective>
Vertical slice for ACCESS-03: a staff member changes their own password through `PUT /api/auth/password`. The change happens only with the correct current password. Every other session of that account is signed out while the current one keeps working. The endpoint is throttled 5 per minute per account, and neither the password nor its hash ever reaches the activity log.

Purpose: the dashboard settings screen needs a password change. This endpoint verifies a secret, so it is also the phase's highest-value brute-force target (D-06). It additionally closes a leak found while planning: `App\Traits\LogsActivity` logs every fillable attribute, `User::$fillable` includes `password`, and Spatie does not honour `$hidden`. So the bcrypt hash is written to `activity_log.attribute_changes` today (on staff creation) and would be on every password change. D-07's "password must never appear in activity properties" needs a real fix.
Output: `StaffPasswordChangeTest`, `ChangePasswordRequest`, `AuthStaffService::changePassword()`, `StaffAuthController::changePassword()`, one throttled route, the activity-log exclusion, two `BaseRequest` mappings, three lang keys in five locales.
</objective>

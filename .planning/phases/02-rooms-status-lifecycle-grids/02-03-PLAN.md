<objective>
Give the front desk read-only 14-day availability and rate grids per room type (ROOMS-03, ROOMS-04; D-08, D-09, D-10, D-11). After Task 2 a receptionist reads the availability grid; after Task 3 the rate grid too.

Purpose: both grids must never disagree with the booking engine. The availability grid reuses CheckAvailabilityAction's exact overlap predicate and is proven equal to `/availability` cell by cell. The rate grid clones the quote's rule chain in `PricingService::nightlyRate` and is proven equal to the one-night quote. Both are bounded in queries so `days` cannot be used to load the database (Pitfall 8).
Output: `ShowFrontDeskGridRequest`, `FrontDeskService::availabilityGrid` and `::ratesGrid`, `PricingService::nightlyRate`, two controller methods, two routes, and three test classes.
</objective>

## Flagged Assumptions

- **FA-03-1 (ROOMS-03 edge probe, category unclassified, left unresolved).** The probe could not classify ROOMS-03. Its likely targets are authored as truths and tests: stays crossing both window edges, null room_id rows, live versus expired holds, overbooking clamped to 0, types with no rooms, maintenance never subtracted, inactive and trashed rooms excluded. The probe row stays unresolved for the verifier.
- **FA-03-2 (pre-existing quote behaviour, MySQL only).** QuoteReservationAction compares `ends_on > check_in` without `whereDate`. SQLite stores date-cast values with a `00:00:00` suffix, so in the test suite a rule applies on its ends_on day, the same as D-10's inclusive window. On MySQL (DATE columns) the quote excludes a rule's last day. The grid follows D-10 (inclusive), so in production the grid and the quote can differ on a rule's final day only. D-10 forbids changing the quote in this phase. Recommendation for the owner: use `whereDate('ends_on', '>=', $checkIn)` in the quote when per-night pricing lands. Recorded as a carry-forward in 02-04's summary.
- **FA-03-3 (rule order).** Both the quote and the grid iterate rules in SQL's natural order with no ordering clause (D-10 as written). The agreement tests use identical rule windows so SQLite returns insertion order on every index; production MySQL could return a different order when overlapping rules have different windows. Pinning `id` order in both paths belongs with the deferred per-night quote work.
- **FA-03-4.** A `weekend`-scope rule applies on every date of its window, weekdays included, because the quote has no day-of-week logic. `rule_scope` is informational. The docs say so.
- **FA-03-5.** `rate_usd` is a two-decimal string (money as DECIMAL, matching `base_price_usd`), although the quote's `daily_rate_usd` is a JSON number. The grid is a new contract, so the string form follows the project's money rule.

# 09.1-05 — deleted accounts on the staff surfaces (D-12)

## Files

- `app/Services/Guest/GuestService.php`: `index()` adds `activeAccounts()` when the `account_status` param is absent. The directory still runs exactly 5 queries (asserted).
- `app/Filters/GuestFilter.php`: `account_status` eq/in.
- `app/Http/Resources/Guest/GuestDirectoryResource.php`, `GuestProfileResource.php`: `account_status`, `account_deleted_at` (ISO-8601, house `toIso8601String()`), appended at the end.
- `app/Actions/Guest/AddGuestNoteAction.php`, `UpdateGuestPreferencesAction.php`: re-read the guest row under `lockForUpdate` inside the transaction; deleted → `GuestAccountDeletedException` (422 `guest_account_deleted`).
- `resources/views/pdf/receipt.blade.php`: falls back to `reservations.last_name`.
- Test `tests/Feature/Guests/DeletedGuestVisibilityTest.php` (18).

## Deviations

- `GuestDirectoryTest::ROW_KEYS` and `GuestProfileTest::TOP_KEYS` assert the exact key list, not a subset as the plan assumed. Both constants gained the two new keys (an additive test edit, not a weakened one).
- `?account_status=bogus` returns 200 with 0 rows, not 422. That is BaseFilter's documented contract: whitelisted eq values are compared, not validated. A blank `?account_status=` is the "All" option and shows active and deleted accounts.
- `UpdateGuestPreferencesAction` previously used no lock; it now takes the guest-row lock to read the status.

## 2. Account deletion (item 2)

### FK inventory (migrations)
- cascade: `service_bookings` (2026_07_12_100004:14), `service_requests` (…100005:14), `guest_documents` (…100008:14), `device_tokens` (2026_07_15_100000:14), `guest_notifications` (…100001:17), `conversations` (…100002:14, and `messages.conversation_id` cascade), `reviews` (2026_07_26_100004:14), `guest_notes` (2026_09_26_120000:20).
- nullOnDelete: `reservations` (2026_07_10_100003:16), `event_inquiries` (2026_07_11_100000:14), `tickets` (2026_07_16_100000:14), `folio_item_disputes` (2026_09_26_130200:25).
- morph: `personal_access_tokens.tokenable`, `messages.sender`, `activity_log.subject/causer`. There's no morph-map entry for Guest (`AppServiceProvider:70` maps only 4 bookables), so the morph type is the FQCN `App\Models\Guest`.
- no FK: `otp_codes.identifier` (E.164 or email).

So hard delete is impossible without losing financial and operational records, and anonymization is required.

### Reusable patterns

- Files: `FileTrait::deleteFile(?string $path, 'public')`.
- Firestore: `MirrorsToFirestore::mirrorToFirestore('chats', $uuid, [...])`, used by `SendMessageAction:69`. Tests bind `NullFirebaseService`.
- Suppress model logging: `activity()->withoutLogging(Closure)` (`vendor/spatie/laravel-activitylog/src/Support/ActivityLogger.php:181`).
- Lock assertions: `tests/Concerns/RecordsRowLocks`. Query budget: `tests/Concerns/CountsDomainQueries`.
- Exceptions: flat `app/Exceptions/*`, `errorCode()`/`statusCode()`. The handler falls back to `custom.errors.<code>`, and the envelope carries `context`.

### Activity-log redaction approach
DB-agnostic: `Activity::where('subject_type', Guest::class)->where('subject_id', $id)->chunkById(200, …)`. Decode `properties` (a cast collection), `unset` the PII keys under `attributes` and `old`, and save via query `update` so no new activity is generated. PHP-side, because SQLite and MySQL JSON functions differ.

### Store policies (context for D-13)
- Apple App Review Guideline 5.1.1(v): apps that support account creation must let users initiate deletion in the app.
- Google Play User Data policy (account deletion): apps that allow account creation must offer in-app deletion and a web link where users can request deletion. Data kept for legitimate reasons (security, fraud, legal) must be disclosed in the Data safety form.
Both allow retention with disclosure, so they are satisfied by D-05..D-13 plus owner actions.

## 3. Exchange rates (item 4)

- No existing currency code (`grep -ri "currenc|exchange|SYP"` over `app/`, `config/` finds only `phone_country => 'SY'`).
- All money is `DECIMAL(10,2)` USD (`reservations.total_usd`, folio `*_usd`), and bcmath helpers live in `App\Support\FolioLedger`.
- `site_settings` (2026_07_30_100300) is a JSON value table edited under `cms.edit`: wrong permission audience, no DECIMAL, no history.
- Permission: `pricing.edit` is seeded (`RolesAndPermissionsSeeder:34`) and inert (`CmsAccessControlTest:125`, `API_GUIDE_DASHBOARD.md:182`).
- Precision: SYP trades in the thousands-to-tens-of-thousands per USD before any redenomination. DECIMAL(20,6) holds 14 integer and 6 fractional digits, which covers both the old and the redenominated pound and TRY (~tens).
- Query plan for current rates: `SELECT * FROM exchange_rates WHERE id IN (SELECT MAX(id) FROM exchange_rates WHERE currency IN (…) GROUP BY currency)`. The `(currency, id)` index serves the group-by, and the call is one statement plus an eager `setBy` for staff (2 total).
- Public list exceptions to `{items, meta}` already exist (`/public/settings`, flat map). FX follows that precedent: a bounded config set.

`App\Support\LoyaltyLedger` (final, non-static, resolved from the container, no constructor dependencies). Class docblock: caller contract (an open DB transaction and the guest row already locked with `lockForUpdate`; this class then locks batch rows — lock order guest → batches, M-6), FIFO = `ORDER BY expires_at, id` (Q14), availability always filters `expires_at > now()` (the sweep is bookkeeping only).

Methods (int guest ids, enums from 10-01):
1. `available(int $guestId): int`.
2. `balances(int $guestId, int $warningDays): array` — one query with conditional sums over the guest's active unexpired batches: keys `available` (int), `expiring_soon` (int, expires_at <= now + warningDays), `next_expiry_at` (?CarbonImmutable, the minimum expires_at).
3. `credit(int $guestId, int $points, LoyaltyBatchSource $source, CarbonImmutable $expiresAt, array $attributes = []): LoyaltyEarnBatch` — points > 0 (LogicException otherwise); points_remaining = points; earned_at now; status active; `$attributes` may set folio_id, awarded_by, reason.
4. `consume(int $guestId, int $points): array` — points > 0; select active unexpired batches `lockForUpdate()` ordered expires_at, id; pre-check the sum and throw `LoyaltyInsufficientPointsException(__('custom.errors.loyalty_insufficient_points'), ['available_points' => ..., 'requested_points' => ...])`; drain in order, `depleted` at 0; return a list of `['batch_id' => int, 'points' => int]`.
5. `record(array $attributes, array $allocations = []): LoyaltyLedgerEntry` — create the entry (`occurred_at` defaults to now) then one allocation row per element; when allocations are given and their sum differs from abs(points), throw LogicException before writing.
6. `refund(LoyaltyLedgerEntry $redeemEntry): LoyaltyLedgerEntry` — return the existing `reversal` when present. Otherwise lock the allocated batches (`lockForUpdate`, by id), restore each eligible one (status active or depleted and expires_at > now) to active with points added back, sum the rest into one new batch via `credit(..., LoyaltyBatchSource::REFUND, LoyaltyProgram::current()->expiresAtFrom(now()))`, then `record()` the refund entry as specified in the must_haves with allocations for every batch credited (restored batches and the new one).
7. `clawback(LoyaltyLedgerEntry $earnEntry): LoyaltyLedgerEntry` — return the existing `reversal` when present. Lock the originating batch; take min(earned, remaining) from it if it is active or depleted; then lock the guest's other active unexpired batches FIFO and take the rest; set the origin to reversed (only if it was active or depleted), emptied others to depleted; `record()` one clawback entry (points = -taken, shortfall_points = earned - taken, allocations for every batch taken from; an entry with points 0 carries no allocations).
8. `expire(LoyaltyEarnBatch $lockedBatch): ?LoyaltyLedgerEntry` — re-read the batch `lockForUpdate`; return null when not active or remaining is 0; else record the expire entry (-remaining, one allocation, key `expire:batch:{id}`) and set remaining 0, status expired.

Every multi-row mutation uses Eloquent saves (no bulk update) so model state stays consistent. No balance column, no caching, no float.
